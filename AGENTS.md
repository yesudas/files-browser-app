# AGENTS.md

Guidance for AI coding agents working in this repo. Read this file first —
it exists specifically so you don't have to grep/read the whole codebase to
orient yourself. It's a plain PHP app (no framework, no build step, no
Composer/npm), so most answers live in a handful of self-contained files.

## What this app is

A password-free public file browser for free Christian e-books/PDFs, backed
by a plain `data/` directory tree on disk. There is no database — everything
is either a file on disk (`data/…`) or a generated JSON/XML artifact sitting
next to the PHP scripts. One admin (`a.php`) manages uploads, renames,
deletes, copyright-takedown reports, the search index, and the sitemap.

## Conventions that matter

- **No shared includes.** Each entry-point PHP file is self-contained and
  duplicates small helpers rather than requiring a common lib. Example: the
  "is this hidden?" logic exists three times with different prefixes:
  `isHidden()`/`isHiddenExtension()` in `index.php`, `idx_isHidden()`/
  `idx_isHiddenExt()` in `i.php`, `sm_isHidden()`/`sm_isHiddenExt()` in
  `sitemap.php`. **If you change the hidden-file/folder rules, update all
  three** (and check `a.php`'s own scan loop, which doesn't hide anything —
  the admin sees everything).
- **Hidden-file rule:** a folder/file is hidden from the public site if its
  name starts with `HIDE` (case-insensitive, `stripos($name,'HIDE')===0`), or
  matches a fixed list of sync/system files (`.DS_Store`, `*.ffs_db`,
  `*.ffs_lock`). The admin ("Hide the Reported File" button in the copyright
  reports view) hides a file by renaming it with a `HIDE - ` prefix — no
  separate flag/database, the filename *is* the state.
- **Path safety pattern**, used everywhere a user-supplied path touches the
  filesystem: resolve with `realpath()`, then check the result starts with
  the trusted base directory (`BASE_DATA_DIR` / `$baseDir`) before doing
  anything with it. Never trust `$_GET`/`$_POST` path strings directly. See
  `resolveDataPath()` in `a.php` for the canonical version (handles
  not-yet-existing paths too via `resolveDataPathNew()`).
- **Admin auth pattern**: `session_name('admin_sess')` + `$_SESSION['admin_ok'] === true`,
  checked at the top of `a.php`, `i.php`, and `sitemap.php`. CSRF token is
  `$_SESSION['csrf_token']`, generated once and reused across all three admin
  pages since they share the same session. Any new admin-only script should
  copy this exact block from `i.php` (it's the smallest example).
- **Admin action dispatch**: in `a.php`, authenticated POST actions are
  handled in one sequential `if ($action === '...')` chain (not a
  switch/router). `verifyCsrf()` is called once at the top of that block, not
  per-action. New actions go in that same chain, each ending by either
  falling through to the normal page render or doing its own
  `header('Location: ...'); exit;` (see `hide_report_file` and
  `delete_report` for the redirect style, used when the action doesn't need
  to show inline form errors).
- **File extension whitelist** (`$ALLOWED_EXT` in `a.php`) gates uploads and
  renames — PHP/script extensions are never allowed, and uploaded files have
  `php_flag engine Off` applied via `.htaccess` inside `data/`... actually
  applied at the site root `.htaccess`, which covers `data/` too since there's
  no separate `.htaccess` inside `data/`.
- **URL encoding for file paths**: the public UI (`index.php`) uses
  `encodeFileParam()` which keeps multi-byte UTF-8 characters raw in the
  address bar (readable Tamil/Hindi filenames) while percent-encoding unsafe
  ASCII. `sitemap.php` instead fully percent-encodes every path segment
  (`sm_encodeParam()`) because sitemap XML `<loc>` values should be fully
  escaped per the sitemap protocol — this is an intentional difference, not
  an inconsistency to "fix".
- **No composer/npm/build step.** Just PHP files served directly. Test
  changes with `php -l file.php` for syntax and, if you need to exercise
  behavior, `php -S localhost:PORT` from the repo root.

## Known gaps to be aware of

- `ADMIN_HASH` in `a.php` is a placeholder (`'ADD-YOUR-BCRYPT-HASH-HERE'`) in
  this repo checkout — admin login will always fail until a real bcrypt hash
  is generated and pasted in (see the comment at the top of `a.php`). Don't
  "fix" this by weakening the check; it's a deployment step for whoever owns
  the live credentials.
- Testing any admin-gated script (`a.php`, `i.php`, `sitemap.php`) end-to-end
  therefore requires either a real hash + login, or a throwaway copy with the
  login check temporarily stubbed out for local verification only (never
  commit a stubbed copy).

## Where to make common changes

- **Change what's visible on the public listing** → `index.php` (rendering)
  + `styles.css`.
- **Add/modify an admin action on files/folders** → `a.php`'s POST handler
  chain, near the existing `create_folder`/`rename`/`delete` blocks.
- **Change what counts as "hidden"** → update all three copies (see
  Conventions above).
- **Change the copyright-report form fields** → modal HTML/JS in
  `index.php` (search for `report-modal`), validation in `report.php`, and
  the review UI in `a.php`'s `?view=reports` branch.
- **Change sitemap URL format, chunk size, or grouping** → `sitemap.php`;
  `SITEMAP_CHUNK_SIZE` constant controls the 10,000-file split threshold.
- **Security header / directory-blocking changes** → `.htaccess`.
